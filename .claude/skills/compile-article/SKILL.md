# 做一篇小红书稿

`AGENTS.md` 是唯一事实源。skill 本身也在探索,哪条不合理就改掉。

## 现阶段的定位

**这个阶段要的是快速涨粉,不是出版级长文。** 长文是后面的事。

每条规则都按这个标准判断:它能不能让更多人停下、看完、点关注。

由此定优先级 —— **封面 > 标题 > 前三行 > 正文**。封面和标题决定有没有人点进来,正文只决定点进来的人会不会看完。力气按这个顺序花,别倒过来。

## 产物

`release/` 平铺,编号接现有最大号:

- `NN-<slug>.md` — 发布稿
- `NN-<slug>.jpg` — 封面 1080×1440
- `NN-<slug>.en.md` — 原文逐字保留,绝不覆盖(有外文原文时)

## 两个栏目

- **主线**:面向不在 AI 圈的普通人。通俗改写,术语当场用人话解释。
- **前沿从业者怎么说**:面向已经在用这些工具的人。忠实翻译,保留术语(AGENTS.md、skill、context、prompt 不通俗化),文首点明"谁、何时、在哪说的"。时效强、出得快,涨粉阶段可以多做。

## 第 1 步:值不值得做

**硬门槛**(任一不过就别做):

- 把 AI 删掉,文章还完整 → 不做。
- 只有观点,没有人、物、机制、数字 → 不做。
- 是新闻复述、跑分、"普通人如何抓住风口" → 不做。

**涨粉门槛**(这个阶段比"文章好不好"更重要):

- 一句话能说清它在讲什么吗?说不清,封面和标题就没法做。
- 普通人看到会不会觉得"这说的就是我"?只会"有意思但不关我事" → 换选题。
- 有没有可争的地方?能引评论的选题,比无懈可击的选题值钱。

不做就停在这里,一句话讲清为什么。

## 第 2 步:先定标题和封面

**在写正文之前定。** 定不下来,说明选题本身不成立。

**标题**(封面上的大字):

- 用中文本来的说法。不搬英文标题语法("为 X 重新思考 Y""当 X 之后""关于 X 的 N 件事")。
- **不拿原文的比喻当标题** —— 比喻是正文才建立起来的东西,读者还没读,看不懂。
- **不要工整对仗**。对仗听着像金句,其实是空壳,一股 AI 味。锋利来自一个具体的、反直觉的断言。
- 写完念一遍:主语有没有滑掉,有没有词被硬当名词用。

**封面**:

- 1080×1440,深色底 `0x0E1013` + 白/浅灰几何母题 + 大留白 + **标题大字**。
- 母题要**画出文章的核心机制**,不是装饰(有损压缩 → 一个圆的格子从细到粗;指数衰减 → 一排按 $e^{-\lambda T}$ 降下去的柱子)。
- **缩略图测试**:缩到 200px 宽还认不出主体,就是废图,重做。满幅排线的老版画、整页文字的书影一律过不了。
- 全站视觉必须一致 —— 读者刷到第三条时要认得出是同一个号。
- 工具只有 ffmpeg(没有 PIL / ImageMagick / rsvg)。`drawbox` 拼几何,`drawtext` 排字(字体 Noto Sans CJK SC):
  ```
  python3 gen.py > vf.txt
  ffmpeg -f lavfi -i "color=c=0x0E1013:s=1080x1440" -vf "$(cat vf.txt)" -frames:v 1 -q:v 2 out.jpg
  ```
- 前沿栏目可以直接用原文自带的图。用他人作品要在文末写清作品、作者、藏馆、授权;自己生成的不用署名。

## 第 3 步:写正文

**正文按节排成图片卡,一节 = 一张卡。**

- **全篇 800 字上限**,超了就砍。这个阶段没人在小红书上读两千字。
- 一节一张卡,**每张卡一个重点**。纯铺垫的内容不能单独占一张卡:并进去,或者删掉。
- **前三行必须是读者自己的事** —— 他正在做、或已经在嘀咕的。不拿"某年某国某公司出了件怪事"开场。
- **正题在第一、二张卡就出现**,不能铺三张卡才揭晓。
- 每节先给判断,再给论证。
- 小标题连起来读是一条完整主干 —— 只看小标题的人也能拿到骨架。
- 一段 60–100 字封顶(手机 4–6 行),超过就拆,一句一层。
- 加黑不超过 3–4 处,只加能独立拎出来的判断,不加解释文。
- **结尾留一个能引发评论的问题或判断** —— 评论带来分发。

其他:

- 文首一行出处:`> 编译自 <作者>,《<原题>》,<出处>,<年份>。`
- 术语躲不开时当场用人话解释;能删的术语直接删,只留功能描述。
- 原文有过时的预测或跑分,用 `> 编者注:` 补一句现状,一篇最多两条。
- 公式用 LaTeX。行内 `$...$` 前后留空格,别贴中文标点,否则 GitHub 不渲染;`\text{中文}` 不渲染,别用。

## 第 4 步:打磨

按篇幅决定投入,别在八百字的稿子上做两千字的功夫。逐句读一遍,盯三样:

- **逻辑**:有没有跳步、前后矛盾;有条件的结论有没有被写成绝对的;关键数字回原始来源核。
- **表达**:有没有含糊、绕、说了等于没说;比喻贴不贴切;有没有把精确的词换成口水话(通俗 ≠ 拉低抽象层次)。
- **可读**:有没有要回读第二遍的句子;指代清不清;同一个词短距离重复;为显得有人味硬凑口语 —— 判废。

## 第 5 步:收尾

- `release/index.md` 末尾加 `- [NN-标题](NN-<slug>.md)`。
- git 作者统一 `yuec-000`。稿子、封面、`index.md` 一起提交。
