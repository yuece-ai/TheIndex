# 编译一篇文章

`AGENTS.md` 是唯一事实源,本 skill 只是把协作步骤排成流程。每一步做完再进下一步,不跳步。

产物放 `release/`,平铺,编号接着现有最大号(`NN-<英文短 slug>`):
- `NN-<slug>.en.md` — 原文,逐字保留,绝不覆盖
- `NN-<slug>.md` — 通俗编译稿
- `NN-<slug>.jpg` — 小红书封面(1080×1440)
- 需要时 `NN-<slug>.zh-en.md` — 逐段中英对照

编号只定文件名,不定发布顺序;上线顺序由用户排(通常解释类、基础类靠前)。

---

## 第 0 步:拿到原文

- 链接优先用 `curl -sL -A "Mozilla/5.0 …"` 抓,提取正文段落,存 `<slug>.en.md`(标题、副标题、作者、日期在前)。
- 抓不到就请用户贴正文。
- 通读一遍。不清楚论证前不进下一步。

## 第 1 步:判定是否值得收录

先过硬门槛(任一不过 → 不收,直接告诉用户为什么):

1. **删掉 AI 后文章还完整吗?** 完整 → 不收。
2. **它咬住了一个具体问题吗?** 一句大白话能说清"它在问什么",且普通人会点头"我也想过";如果反应是"有意思,但不是我的事" → 选题或切入口有问题。
3. **里面有人、物、机制或选择吗?** 只有观点、没有具体载体 → 不收。
4. **它是新闻 / 参数复述 / "普通人如何抓住机会"吗?** 是 → 不收。知觉之门不追发布。

再过价值门槛:

5. **它能收回到一个问题,然后要么落一个判断,要么抛一个更深的问题吗?** 只是"一个有趣的研究" → 不够。
6. **读者读完,会重新打量自己生活里的什么?** 说不出来 → 还不成熟。
7. **文章本身够好、够自足吗?** 论证靠定义硬撑、或半篇是易腐的预测和跑分 → 只适合当"多来源里的一个",不适合整篇编译,建议用户改走原创稿。
8. **立场会不会和 `release/` 里已有的稿雷同?** 现有稿如果已经几篇都在讲"AI 侵蚀了某种人的能力",再来一篇同调的会把号做成"AI 怀疑号"。提示用户,让他决定是否仍要收,或换一篇补别的栏目/别的立场(经营决策、前沿、有现场、偏正面或混合)。

输出:一句结论(收 / 不收)+ 逐条理由。不收就停在这里。

## 第 2 步:通俗编译(按 AGENTS.md《编译》)

- **验收标准:一个受过教育的普通读者,每句话第一遍就读懂。一个懂技术的人读着卡壳,就是没做完。**
- 保留论证和作者的语气、第一人称转述("Sacasas 说""他觉得"),不保留原文的句式和抽象度。
- 每一个抽象论断都要落成具体的事或一个日常例子。译到抽象处停下来问:这句话能还原成人、物、机制、数字或决定吗?不能就重写。
- 引文改成转述,只留带画面的那几句(如"引开看门狗的肉""就着盐吸可卡因")。哲学家引哲学家的链条压掉;次要来源压成一两句。
- 删原文的开场客套、邮件通讯说明、写给订户的旁白、文末推荐阅读。
- 术语躲不开时当场用人话解释;能删的术语名字直接删,只留功能描述。
- 原文若是几年前的,内容里有已经过时的经验、预测或跑分:不改原意,在正文里用方框 `> 编者注:…` 补一句现在的情况(这也正是知觉之门"过几个月回来核对"的做法)。编者注自带标签,少而准,一篇最多两三条。
- 文首只放一行出处:`> 编译自 <作者>,《<原题>》,<出处>,<年份>。` 不写"通俗改写""不逐句直译""英文原文见…"之类的说明,那些是全站惯例,写进 `release/index.md` 一次就够。
- 有公式就用 LaTeX(GitHub 渲染):行内 `$...$`,单独成行 `$$...$$`。不要写成"e 的 −λT 次方"这种。

## 第 3 步:三轮打磨(逻辑性 / 表达性 / 可读性)

**逐字逐句过**,不是通读一遍找大问题。三轮,每轮只盯一个维度,每轮都从头读全文,把问题逐条改掉再进下一轮。

**第一轮 —— 逻辑性**
- 论证链条有没有断口:每一步推论跟得上上一步吗?有没有跳步、偷换概念、前后矛盾?
- 结论是真的从前面推出来的,还是硬接上去的?
- 一个较真的反对者会从哪一句插进来?那句得补严。
- 有条件的结论有没有被写成绝对的;关键数字、因果方向,回原始来源核。

**第二轮 —— 表达性**
- 每句话有没有把想说的意思说准、说到位;有没有含糊、绕、说了等于没说的地方。
- 比喻贴不贴切,例子对不对得上要讲的点。
- 关键判断有没有被埋在一堆铺垫里;该重的地方重了没有。
- 术语躲不开时当场用人话解释;能删的术语名字直接删。

**第三轮 —— 可读性**
- 目标读者从头顺下来,有没有要回读第二遍的句子。
- 指代清不清("它""这个""他们"指谁);连接词生不生硬;同一个词短距离重复。
- 句子头重脚轻、一句话绕三层、破折号里套太长的从句。
- 节奏:该快的地方快,该停的地方停;可删的字词删掉。
- 假人味:为显得有人味而抖机灵、硬凑口语——判废。

三轮做完,把每轮"挑出的问题 → 改法"给用户看。

## 第 4 步:分段标题 + 加黑

- **小标题**:一节一个意思。标题要说清这节在讲什么,不能含糊(反面例子:"太顺手了""老媒介研究者早说过" —— 读者不知道指什么)。也不表演聪明。
- **加黑**:默认不加。加黑 = 宣称这是金句。只有满足才加:
  - 是一句能独立拎出来的判断或转折,不是加黑的解释文;
  - 简洁、有刀口、能吸引人往下读;
  - 全篇加黑不超过 3–4 处,多了就稀释。
- 加完自己数一遍加黑处,逐个问:这是金句吗?不是就取消。

## 第 5 步:配图(小红书封面)

这张图是小红书封面,不是普通插图。全站必须**尺寸一致、风格统一**。

**硬规格:**
- 竖版 3:4,统一裁成 **1080 × 1440**,所有文章一张不差。
- 一律用**公共领域的艺术作品**:绘画、素描、版画/铜版画、手稿书页、天文/几何/博物学图版。调性只有两种——**人文感**或**数学之美**。
- 不用:照片、技术示意图、前后对比图、图表、AI 插画、带"科技感"的通用图。
- 不用:吓人的(尸体、解剖、监狱、酷刑)、宗教题材、血腥或压抑的画面。要沉静、克制、耐看。
- 不在图上加文字(标题在小红书编辑器里加)。
- 来源:Met Open Access、Rijksmuseum、美国国家美术馆(NGA)、Smithsonian Open Access、Wikimedia 明确公共领域。

**选图:**
- 优先和文章的核心意象呼应,让读过文章的人会心(例:讲"从有损拷贝里找原文"→ 一张палимпсест或一幅"临摹自某大师"的复制版画)。
- 呼应不上时,选一张气质对、符合上面调性的,不硬凑主题,不选俗图。

**处理(有 ffmpeg,没有 PIL/ImageMagick):**
```
ffmpeg -i in.jpg -vf "crop='min(iw,ih*3/4)':'min(ih,iw*4/3)',scale=1080:1440" -q:v 3 release/<slug>.jpg -y
```
裁前先看构图,`crop` 的 x/y 偏移调到主体居中或按需偏移。

**落地:**
- 存 `release/NN-<slug>.jpg`,和文章一起提交,在 `NN-<slug>.md` 正文最开头用 Markdown 图片语法,alt 一句话说清图和文章的关系。
- 文末一行写清:作品名、作者、藏馆、授权(公共领域 / CC 协议)。
- 定稿前确认:真实存在的作品、尺寸正好 1080×1440、调性和全站一致、不吓人、不宗教题材。

## 第 6 步:更新索引

在 `release/index.md` 末尾加一行:`- [NN-标题](NN-<slug>.md)`。链接文字是"编号-标题"。
